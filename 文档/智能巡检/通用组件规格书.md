# 通用组件规格书

> 适用范围：后台管理类页面、仪表盘、列表页、详情页、弹窗、抽屉、表格、筛选区。
> 目标：统一组件结构、属性、状态、交互、样式边界，降低前端和 IDE 重复造轮子的概率。

## 0. 审阅标记说明

- `【新增】`：本次新增内容，建议重点审阅
- `【删除建议】`：建议后续从旧页面、旧组件、旧实现中移除或替换的内容

## 1. 全局组件规则

### 1.1 组件设计原则

【新增】统一要求：

1. 优先做“通用业务组件”，不要每个页面直接堆原始 `el-*` 组件。
2. 通用组件必须区分：
   - 结构职责
   - 视觉职责
   - 业务职责
3. 组件视觉必须使用设计系统 token，不允许内部硬编码颜色、字号、圆角、阴影、间距。
4. 组件必须优先支持 `loading / empty / disabled / error` 等基础状态。
5. 页面只能组合通用组件，不应在页面层重复实现相同结构。

### 1.2 组件输出规范

【新增】每个通用组件至少应定义以下内容：

| 项目 | 说明 |
|------|------|
| 组件名 | 统一命名，建议 PascalCase |
| 使用场景 | 该组件解决什么问题 |
| 结构组成 | 由哪些区块组成 |
| 必填 props | 页面接入时必须传什么 |
| 可选 props | 可配置项 |
| 事件 | 对外暴露哪些交互事件 |
| 状态 | loading / empty / disabled / error / selected 等 |
| 默认样式 | 高度、间距、圆角、字号等 |
| 禁止项 | 哪些实现方式不允许出现 |

### 1.3 统一禁止项

【删除建议】以下做法不建议继续存在：

- 页面直接复制一份筛选区结构，不抽组件
- 每个列表页自己实现一套表头、分页、空态
- 状态徽标在不同页面各写一套颜色逻辑
- 弹窗底部按钮顺序每页都不一样
- 同一组件在不同页面用不同 class 名和不同 spacing

## 2. PageHeader

### 2.1 组件职责

【新增】`PageHeader` 用于统一后台页面顶部标题区，负责：

1. 页面标题展示
2. 副标题或说明展示
3. 右侧主操作区承载
4. 面包屑或返回入口承载

### 2.2 结构定义

【新增】标准结构：

```text
PageHeader
|- left
|  |- back / breadcrumb（可选）
|  |- title
|  |- subtitle（可选）
|- right
   |- primaryAction
   |- secondaryActions（可选）
```

### 2.3 必填 props

【新增】推荐最小 props：

| prop | 类型 | 说明 |
|------|------|------|
| `title` | `string` | 页面标题 |
| `primaryActions` | `ActionItem[]` | 右侧主操作 |

### 2.4 可选 props

【新增】推荐扩展 props：

| prop | 类型 | 说明 |
|------|------|------|
| `subtitle` | `string` | 页面副标题 |
| `breadcrumb` | `BreadcrumbItem[]` | 面包屑 |
| `showBack` | `boolean` | 是否显示返回按钮 |
| `secondaryActions` | `ActionItem[]` | 次级操作 |
| `sticky` | `boolean` | 是否吸顶 |

### 2.5 样式规则

【新增】统一建议：

| 项目 | 规范 |
|------|------|
| 标题字号 | `--sys-font-size-16` |
| 标题字重 | `--sys-font-weight-600` |
| 副标题字号 | `--sys-font-size-12` |
| 左右布局间距 | `--sys-space-16` |
| 区块底部间距 | `--biz-section-gap` 或 `--sys-space-16` |
| 吸顶层级 | `--sys-z-sticky` |

### 2.6 禁止项

【删除建议】不建议：

- 页面自己写一个 `div + h2 + button`
- 标题区每页高度不同
- 右侧按钮左对齐或居中
- 副标题有的用灰字，有的用浅白字，没有统一 token

## 3. FilterBar

### 3.1 组件职责

【新增】`FilterBar` 用于统一列表页和仪表盘顶部筛选区，负责：

1. 承载输入框、下拉、日期、标签筛选项
2. 管理查询、重置、高级筛选入口
3. 控制多行换行和折叠展开行为

### 3.2 结构定义

【新增】标准结构：

```text
FilterBar
|- fields
|  |- FilterItem...
|- actions
|  |- search
|  |- reset
|  |- more（可选）
```

### 3.3 必填 props

【新增】推荐最小 props：

| prop | 类型 | 说明 |
|------|------|------|
| `modelValue` | `Record<string, any>` | 当前筛选值 |
| `items` | `FilterItem[]` | 筛选项配置 |

### 3.4 必备事件

【新增】统一建议：

| 事件 | 说明 |
|------|------|
| `search` | 点击查询 |
| `reset` | 点击重置 |
| `update:modelValue` | 筛选值变化 |
| `toggle-advanced` | 切换高级筛选 |

### 3.5 样式规则

【新增】统一建议：

| 项目 | 规范 |
|------|------|
| 控件高度 | `--comp-input-height-md` / `--comp-select-height-md` |
| 控件间距 | `--biz-filter-gap` |
| 单行最小高度 | `--comp-filter-row-min-height` |
| 行间距 | `--sys-space-8` |
| 按钮顺序 | `查询 -> 重置 -> 高级筛选` |

### 3.6 交互规则

【新增】统一建议：

1. 单行放不下时，先换成两行。
2. 两行仍拥挤时，收敛为“高级筛选”折叠面板。
3. 查询按钮始终靠近筛选区右侧，不允许掉到孤立第三行。
4. 重置后应恢复默认值，并触发刷新。

### 3.7 禁止项

【删除建议】不建议：

- 某些页面把“重置”放在“查询”前面
- 某些页面没有重置按钮
- 高级筛选直接用文字链接，有些页面又用按钮
- 筛选区换行后按钮漂到底部单独一行

## 4. CommonTable

### 4.1 组件职责

【新增】`CommonTable` 用于统一后台表格的表头、行高、空态、加载态、分页承载方式。

### 4.2 结构定义

【新增】标准结构：

```text
CommonTable
|- toolbar（可选）
|- table
|- empty / loading / error
|- pagination（可选）
```

### 4.3 必填 props

【新增】推荐最小 props：

| prop | 类型 | 说明 |
|------|------|------|
| `columns` | `TableColumn[]` | 列配置 |
| `dataSource` | `any[]` | 表格数据 |
| `rowKey` | `string | Function` | 行唯一键 |

### 4.4 可选 props

【新增】推荐扩展 props：

| prop | 类型 | 说明 |
|------|------|------|
| `loading` | `boolean` | 是否加载中 |
| `pagination` | `PaginationConfig | false` | 是否分页 |
| `selectable` | `boolean` | 是否多选 |
| `striped` | `boolean` | 是否斑马纹 |
| `showOverflowTooltip` | `boolean` | 是否默认省略并展示 tooltip |
| `emptyText` | `string` | 空文案，默认来自统一规范 |

### 4.5 列规范

【新增】每列至少应明确以下信息：

| 字段 | 说明 |
|------|------|
| `key` | 列 key |
| `title` | 表头文案 |
| `dataIndex` | 数据字段 |
| `width` | 列宽或最小列宽 |
| `align` | 对齐方式 |
| `ellipsis` | 是否超长省略 |
| `renderType` | text / tag / status / action / link / custom |

### 4.6 样式规则

【新增】统一建议：

| 项目 | 规范 |
|------|------|
| 表头背景 | `--comp-table-header-bg` |
| 行高 | `--comp-table-row-height` |
| 正文字号 | `--sys-font-size-12` |
| 正文行高 | `--sys-line-height-20` |
| 空值文案 | `--` |
| 操作列按钮间距 | `--sys-space-8` |

### 4.7 交互规则

【新增】统一建议：

1. 操作列按钮超过 3 个时收敛为“更多”。
2. 超长文本必须明确采用：
   - 单行省略 + tooltip
   - 多行截断
   - 自动换行
3. 空数据时显示 `EmptyState`，不展示裸文字。
4. 加载中时不闪空态。

### 4.8 禁止项

【删除建议】不建议：

- 每页自己决定空值是 `-` 还是 `/`
- 某些表格行高 40px，某些 48px
- 操作列一会儿文本按钮，一会儿图标按钮，没有规则
- 文本截断逻辑每页各写各的

## 5. StatusBadge

### 5.1 组件职责

【新增】`StatusBadge` 用于统一执行状态、风险等级、启停状态、在线状态等视觉表达。

### 5.2 必填 props

【新增】推荐最小 props：

| prop | 类型 | 说明 |
|------|------|------|
| `value` | `string` | 状态值 |
| `type` | `execution | risk | switch | online | custom` | 状态类型 |

### 5.3 可选 props

【新增】推荐扩展 props：

| prop | 类型 | 说明 |
|------|------|------|
| `showDot` | `boolean` | 是否显示状态点 |
| `size` | `sm | md` | 尺寸 |
| `tooltip` | `string` | 补充说明 |

### 5.4 样式规则

【新增】统一建议：

| 项目 | 规范 |
|------|------|
| 高度 | `--comp-status-badge-height` |
| 圆角 | `--sys-radius-pill` |
| 内边距 | `0 8px` |
| 字号 | `--sys-font-size-12` |
| 点与文案间距 | `--sys-space-4` |

### 5.5 禁止项

【删除建议】不建议：

- 不同页面状态标签颜色不同
- 同一状态有时加点，有时不加点，没有标准
- 组件内部把接口状态值直接翻译成中文且无法配置

### 6.3 必填 props

【新增】推荐最小 props：

|------|------|------|

### 6.4 可选 props

【新增】推荐扩展 props：

| prop | 类型 | 说明 |
|------|------|------|
| `description` | `string` | 副文案 |
| `image` | `string` | 插画地址 |

## 7. DialogForm / DrawerForm

### 7.1 组件职责

【新增】`DialogForm` / `DrawerForm` 用于承载新增、编辑、查看详情等中小型表单场景。

### 7.2 标准结构

【新增】标准结构：

```text
DialogForm / DrawerForm
|- header
|- body
|  |- form
|- footer
   |- secondaryAction
   |- primaryAction
```

### 7.3 必填 props

【新增】推荐最小 props：

| prop | 类型 | 说明 |
|------|------|------|
| `visible` | `boolean` | 是否打开 |
| `mode` | `create | edit | detail` | 当前模式 |
| `schema` | `FormField[]` | 表单项配置 |

### 7.4 必备状态

【新增】统一建议：

| 状态 | 表现 |
|------|------|
| `init` | 首次加载 skeleton 或 loading |
| `editing` | 正常可编辑 |
| `readonly` | 不可编辑，仅查看 |
| `submitting` | 主按钮 loading，禁止重复提交 |
| `submitError` | 保留用户输入并展示错误 |

### 7.5 交互规则

【新增】统一建议：

1. 主按钮默认放右侧，次按钮放左侧或其左边。
2. 危险操作必须二次确认。
3. 关闭时如有未保存修改，应提示确认离开。
4. 详情态不展示保存按钮。

### 7.6 样式规则

【新增】统一建议：

| 项目 | 规范 |
|------|------|
| 标题区高度 | `--comp-dialog-header-height` |
| 内容区内边距 | `--sys-space-16` 或 `--sys-space-24` |
| 底部按钮间距 | `--sys-space-8` |
| 圆角 | `--sys-radius-8` |

### 7.7 禁止项

【删除建议】不建议：

- 有的弹窗底部按钮左对齐，有的右对齐
- 有的详情态仍显示“保存”
- 提交中仍允许重复点击确认按钮

【新增】`DashboardCard` 用于统一仪表盘中的指标卡、图表卡、列表卡、说明卡。

### 8.2 标准结构

【新增】标准结构：

```text
DashboardCard
|- header
|  |- title
|  |- extra（可选）
|- body
|- footer（可选）
```

### 8.3 样式规则

【新增】统一建议：

| 项目 | 规范 |
|------|------|
| 容器背景 | `--sys-color-bg-panel` |
| 头部高度 | `--comp-card-header-height` |
| 内边距 | `--sys-space-16` |
| 圆角 | `--sys-radius-6` |
| hover 阴影 | `--sys-shadow-sm` |

### 8.4 禁止项

【删除建议】不建议：

- 仪表盘卡片各自使用不同内边距
- 有的卡片标题 14px，有的 16px，没有规则
- KPI 卡与普通信息卡结构完全不一致，无法复用

## 9. 给 IDE / AI 的使用说明

【新增】把本规格书交给 IDE 或 AI 时，建议附加以下要求：

```md
1. 页面实现优先使用本规格书中的通用组件，不要直接在页面层拼装原始组件。
2. 如果发现设计稿中出现重复结构，优先判断是否应抽成通用组件。
3. 组件必须输出：
   - props 设计
   - 事件设计
   - 状态设计
   - token 使用说明
4. 不允许组件内部写死状态文案、空值文案、反馈文案。
5. 如果某组件规格缺失，先补“组件规格建议”，再写实现代码。
```
