# 页面生成约束

> 适用范围：使用 Cursor、Copilot、Claude Code、OpenAI Codex 等 IDE / AI 工具生成前端页面、通用组件、样式文件时。
> 目标：统一页面生成时的输入格式、输出格式、实现顺序、缺失信息回报方式、代码交付标准，减少 AI 生成页面时的漂移和返工。

## 0. 审阅标记说明

- `【新增】`：本次新增内容，建议重点审阅
- `【删除建议】`：建议后续从旧提示词、旧页面生成流程、旧协作方式中移除或替换的内容

## 1. 总体原则

### 1.1 页面生成优先级

【新增】生成页面时必须遵循以下优先级：

1. 优先服从设计稿
2. 设计稿未定义时，服从设计系统规范
3. 设计系统未定义时，服从状态枚举与文案规范
4. 页面结构不清晰时，服从通用组件规格书
5. 以上都缺失时，先回报缺失信息，不允许直接脑补

### 1.2 页面生成目标

【新增】AI / IDE 生成页面时，不只是“把界面拼出来”，而是要同时满足：

1. 视觉尽可能贴近设计稿
2. 结构可以复用
3. 样式可以维护
4. 状态完整
5. 代码可直接接入项目

### 1.3 明确禁止项

【删除建议】以下做法不建议继续使用：

- 只给一句“照着设计稿写个页面”
- 不给页面类型、不说是列表页还是详情页
- 不提供状态规则，让 AI 自己猜
- 让 AI 直接输出一整个超大单文件组件
- 页面写出来后才发现 token、状态、组件命名全不统一

## 2. 给 IDE / AI 的最小输入要求

### 2.1 必填输入项

【新增】每次让 IDE / AI 生成页面时，至少提供以下信息：

| 输入项 | 是否必填 | 说明 |
|------|------|------|
| 页面名称 | 是 | 例如：`主机管理`、`联合巡检任务详情` |
| 页面类型 | 是 | 列表页 / 详情页 / 仪表盘 / 弹窗 / 抽屉 / 配置页 |
| 参考设计稿 | 是 | Sketch 页面名、画板名、截图来源 |
| 主要模块 | 是 | 页面由哪些区块组成 |
| 关键交互 | 是 | 查询、重置、新建、编辑、删除、分页、Tab、图表联动等 |
| 数据展示类型 | 是 | 表格 / 表单 / 图表 / 卡片 / 描述列表 |
| 优先复用组件 | 否 | PageHeader、FilterBar、CommonTable 等 |
| 特殊约束 | 否 | 如固定表头、超长文本 tooltip、必须暗色主题等 |

### 2.2 推荐输入模板

【新增】建议统一按以下格式提交任务：

```md
页面名称：{页面名称}
页面类型：{列表页 / 详情页 / 仪表盘 / 弹窗 / 抽屉}
参考设计稿：{Sketch 页面 / 画板}
主要模块：
- {模块1}
- {模块2}
- {模块3}

关键交互：
- {交互1}
- {交互2}
- {交互3}

数据展示类型：
- {表格 / 表单 / 图表 / 描述列表 / 卡片}

优先复用组件：
- {PageHeader / FilterBar / CommonTable / StatusBadge / EmptyState}

特殊约束：
- {例如：列表页需要固定操作列}
- {例如：图表空态必须和设计稿一致}
```

## 3. IDE / AI 的标准输出格式

### 3.1 必须输出的内容

【新增】每次页面生成结果必须包含以下部分：

| 输出项 | 必须内容 |
|------|------|
| 页面结构拆解 | 页面分为哪几个模块 |
| 组件树建议 | 页面级组件和子组件拆分 |
| token 使用说明 | 使用了哪些颜色、字号、间距、圆角、阴影 token |
| 状态清单 | loading / empty / error / disabled / readonly 等 |
| 缺失信息清单 | 设计稿或规范未明确的部分 |
| 风险与假设 | 哪些实现是按规范推断的 |
| 最终代码 | 页面代码、子组件代码、必要样式 |

### 3.2 推荐输出模板

【新增】建议 IDE / AI 按以下顺序输出：

```md
## 页面结构
- ...

## 组件拆分
- ...

## 使用的通用组件
- ...

## token 使用清单
- ...

## 状态清单
- ...

## 缺失信息
- ...

## 风险与假设
- ...

## 最终代码
``` 

### 3.3 禁止的输出方式

【删除建议】不建议：

- 直接上来就贴代码，不说明结构
- 不列缺失信息，直接脑补
- 不说明用了哪些通用组件
- 一股脑输出 500 行单文件代码，不做拆分说明

## 4. 页面生成顺序

### 4.1 标准实现顺序

【新增】页面生成应遵循以下顺序：

1. 识别页面类型
2. 拆分页面模块
3. 对照已有通用组件
4. 标记缺失信息
5. 先输出结构和组件方案
6. 再生成页面代码
7. 最后补充样式和状态处理

### 4.2 页面类型识别规则

【新增】建议统一如下：

| 页面类型 | 典型结构 |
|------|------|
| 列表页 | `PageHeader + FilterBar + CommonTable + Pagination` |
| 详情页 | `PageHeader + SummaryCard / DescriptionBlock + RelatedTable / Tabs` |
| 仪表盘 | `PageHeader + KPI Cards + Charts + RecentList` |
| 弹窗表单 | `DialogForm` |
| 抽屉表单 | `DrawerForm` |
| 配置页 | `PageHeader + ConfigBlock + Form/Table Mixed Layout` |

## 5. 页面拆分规则

### 5.1 拆分原则

【新增】页面拆分时必须遵循：

1. 顶层页面只负责组织模块，不承载复杂 UI 细节
2. 重复出现两次及以上的区块优先抽为子组件
3. 具有统一交互模式的区块优先复用通用组件
4. 单个文件过长时，应优先拆分子组件而不是继续堆逻辑

### 5.2 推荐拆分粒度

【新增】建议粒度如下：

| 场景 | 推荐做法 |
|------|------|
| 页面骨架 | 保留在页面主文件 |
| 筛选区 | 尽量复用 `FilterBar` |
| 表格区 | 尽量复用 `CommonTable` |
| 状态徽标 | 使用 `StatusBadge` |
| 空态 | 使用 `EmptyState` |
| 指标卡 | 抽为 `MetricCard` 或复用 `DashboardCard` |
| 描述信息块 | 抽为 `DescriptionBlock` |

### 5.3 禁止的拆分方式

【删除建议】不建议：

- 所有内容写进一个 `.vue` 文件
- 页面、子组件、工具函数、mock 数据混在一起
- 组件拆得过碎，形成大量一次性壳组件

## 6. 样式生成约束

### 6.1 样式职责边界

【新增】样式文件职责必须清晰：

| 文件 | 职责 |
|------|------|
| `variables.scss` | token 定义 |
| `override.scss` | 全局组件覆盖 |
| `custom.scss` | 业务通用布局 |
| 页面 `scoped style` | 当前页面局部样式 |

### 6.2 样式规则

【新增】统一要求：

1. 禁止新增字面量颜色、字号、圆角、阴影、间距，除非先登记缺失 token。
2. 优先使用设计系统 token。
3. 页面布局优先使用统一骨架和统一 spacing。
4. 表格、按钮、输入类控件高度必须与通用组件规格书保持一致。

### 6.3 样式禁止项

【删除建议】不建议：

- 页面 scoped style 中重新声明一套主题色
- 页面里直接写大量 `margin: 13px 18px`
- 每页单独改按钮高度、圆角、字号

## 7. 状态处理约束

### 7.1 必备状态

【新增】不同页面最少应处理以下状态：

| 页面类型 | 必备状态 |
|------|------|
| 列表页 | `loading / empty / error / hasData` |
| 详情页 | `loading / error / readonly / hasData` |
| 表单页 | `init / editing / submitting / submitError / readonly` |
| 仪表盘 | `loading / empty / partialEmpty / hasData` |

### 7.2 状态来源

【新增】统一要求：

1. 页面状态优先来自接口与页面级 store / state。
2. 文案展示必须来自状态枚举与文案规范，不允许页面内部散落写死。
3. 未识别状态统一回落为 `unknown`。

## 8. 缺失信息处理约束

### 8.1 必须中止脑补的场景

【新增】遇到以下情况时，IDE / AI 必须先回报缺失信息，而不是直接实现：

| 场景 | 需要确认的内容 |
|------|------|
| 表格设计不完整 | 列宽、操作列、空值规则 |
| 状态不明确 | 状态枚举、状态文案、颜色映射 |
| 弹窗规范不完整 | 宽度、高度、底部按钮顺序 |
| 图表设计不完整 | 图例、tooltip、空态、颜色映射 |
| 表单设计不完整 | 校验规则、必填项、字段禁用逻辑 |

### 8.2 回报模板

【新增】建议统一如下：

```md
缺失信息清单：
1. ...
2. ...
3. ...

建议补充：
1. ...
2. ...
```

## 9. 代码交付标准

### 9.1 最小交付物

【新增】每次页面生成至少应产出：

| 交付物 | 说明 |
|------|------|
| 页面主文件 | 页面入口组件 |
| 子组件 | 被拆分出的可复用模块 |
| 样式文件 | 必要页面样式或组件样式 |
| 常量/映射 | 状态映射、列配置、筛选配置等 |
| 说明文档 | 结构说明、缺失信息、风险说明 |

### 9.2 代码质量要求

【新增】统一要求：

1. 命名清晰，组件名使用 PascalCase。
2. 不在模板里堆大段匿名逻辑。
3. 状态映射、列配置、筛选项配置优先提取。
4. 不在页面中直接写死状态中文映射。
5. 不混用同类基础组件库。

### 9.3 禁止的交付方式

【删除建议】不建议：

- 只给截图式代码，不给结构说明
- 只输出一个页面文件，不拆任何复用逻辑
- 不说明假设，直接把缺失信息默认为“设计如此”

## 10. 页面验收要求

### 10.1 自检清单

【新增】页面交付前至少检查：

| 检查项 | 验收标准 |
|------|------|
| 页面骨架 | 是否符合页面类型的标准结构 |
| 通用组件复用 | 是否优先使用了 `PageHeader / FilterBar / CommonTable / StatusBadge / EmptyState` |
| token 使用 | 是否存在硬编码视觉字面量 |
| 状态完整性 | loading / empty / error / disabled 等是否齐全 |
| 文案一致性 | 是否符合状态枚举与文案规范 |
| 样式职责 | 是否没有越权改 token 或全局组件规则 |
| 缺失信息登记 | 是否对不明确部分做了说明 |

## 11. 给 IDE / AI 的最终执行模板

【新增】下面这段可以直接作为页面生成总提示词使用：

```md
请按照以下顺序完成页面实现：

1. 根据设计稿和《设计系统规范-严格可落地版.md》判断页面类型
2. 优先复用《通用组件规格书.md》中的通用组件
3. 所有状态文案、空值文案、按钮文案优先复用《状态枚举与文案规范.md》
4. 如果存在未定义的列宽、状态、弹窗尺寸、空态文案，先输出缺失信息清单，不要直接脑补
5. 输出内容必须包含：
   - 页面结构
   - 组件拆分
   - token 使用清单
   - 状态清单
   - 缺失信息清单
   - 风险与假设
   - 最终代码
6. 不允许：
   - 混用同类基础组件库
   - 新增未登记的视觉 token
   - 页面中硬编码状态文案
   - 不拆分的大型单文件实现
```
