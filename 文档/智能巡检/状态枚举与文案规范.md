# 状态枚举与文案规范

> 适用范围：后台列表页、详情页、仪表盘、弹窗、抽屉、表格、表单、图表、空态、提示反馈。
> 目标：统一页面中的状态值、展示文案、颜色映射、空值文案、按钮文案，避免前端或 IDE 自行发明。

## 0. 审阅标记说明

- `【新增】`：本次新增内容，建议重点审阅
- `【删除建议】`：建议后续从旧规范、旧页面、旧组件中移除或替换的内容

## 1. 基本规则

### 1.1 状态字段规则

【新增】统一要求：

1. 接口状态值优先使用英文枚举，不直接以中文文案作为业务值。
2. 页面展示文案与接口值分离，禁止把中文文案写死在组件内部。
3. 一个状态必须同时定义：
   - `value`
   - `label`
   - `colorToken`
   - `bgToken`
   - `sortOrder`
4. 同一语义状态在不同页面必须使用相同文案，不允许一个页面叫“执行中”，另一个页面叫“进行中”。
5. 未定义状态统一降级为 `unknown`，展示为 `未知`，不得空白。

### 1.2 文案使用规则

【新增】统一要求：

1. 按钮文案优先使用动词短语，如 `新建`、`保存`、`删除`、`查看详情`。
2. 空态文案必须包含主文案，副文案按需提供。
3. 提示文案优先简洁明确，不写口语化或模糊表达。
4. 成功、失败、警告类反馈文案应可直接复用，不允许每页自由发挥。

【删除建议】以下写法不建议继续使用：

- `处理中...`
- `操作成功！`
- `暂无数据～`
- `请稍后重试吧`

原因：语气不统一、可复用性差、对 AI/IDE 约束弱。

## 2. 通用状态枚举

### 2.1 执行状态

【新增】推荐作为巡检任务、异步任务、批处理任务的统一枚举：

| value | 展示文案 | 说明 | 前景色 token | 背景色 token | 排序 |
|------|------|------|------|------|------|
| `pending` | `待执行` | 尚未开始 | `--sys-text-secondary` | `transparent` | `10` |
| `queued` | `排队中` | 已进入队列等待执行 | `--sys-color-info-default` | `var(--sys-color-brand-primary-soft)` | `20` |
| `running` | `执行中` | 正在执行 | `--sys-color-info-default` | `var(--sys-color-brand-primary-soft)` | `30` |
| `partial_success` | `部分成功` | 部分对象成功，部分失败 | `--sys-color-warning-default` | `rgba(255,141,31,0.12)` | `40` |
| `success` | `执行成功` | 全部成功 | `--sys-color-success-default` | `rgba(40,198,77,0.12)` | `50` |
| `failed` | `执行失败` | 全部失败或关键失败 | `--sys-color-danger-default` | `rgba(245,78,78,0.12)` | `60` |
| `canceled` | `已取消` | 用户或系统取消 | `--sys-text-secondary` | `rgba(195,197,206,0.10)` | `70` |
| `timeout` | `执行超时` | 超过时限未完成 | `--sys-color-warning-default` | `rgba(255,141,31,0.12)` | `80` |
| `unknown` | `未知` | 无法识别的状态 | `--sys-text-placeholder` | `rgba(120,123,146,0.12)` | `999` |

【新增】建议前端维护如下映射结构：

```ts
export const EXECUTION_STATUS_MAP = {
  pending: { label: '待执行' },
  queued: { label: '排队中' },
  running: { label: '执行中' },
  partial_success: { label: '部分成功' },
  success: { label: '执行成功' },
  failed: { label: '执行失败' },
  canceled: { label: '已取消' },
  timeout: { label: '执行超时' },
  unknown: { label: '未知' },
}
```

### 2.2 风险等级

【新增】推荐作为告警、漏洞、巡检结论、风险规则的统一枚举：

| value | 展示文案 | 说明 | 前景色 token | 背景色 token | 排序 |
|------|------|------|------|------|------|
| `low` | `低风险` | 低优先级问题 | `--sys-color-success-default` | `rgba(40,198,77,0.12)` | `10` |
| `medium` | `中风险` | 需要关注 | `--sys-color-warning-default` | `rgba(255,141,31,0.12)` | `20` |
| `high` | `高风险` | 高优先级问题 | `#FF5E2F` | `rgba(255,94,47,0.12)` | `30` |
| `critical` | `严重风险` | 最高优先级问题 | `--sys-color-danger-default` | `rgba(245,78,78,0.12)` | `40` |
| `unknown` | `未知` | 无法识别 | `--sys-text-placeholder` | `rgba(120,123,146,0.12)` | `999` |

【删除建议】不建议继续混用以下文案：

- `低危 / 中危 / 高危 / 严重`
- `低 / 中 / 高 / 严重`
- `一般 / 较高 / 严重`

建议统一为：`低风险 / 中风险 / 高风险 / 严重风险`

## 3. 数据为空时的统一文案

### 3.1 空值展示

【新增】字段级空值统一规范：

| 场景 | 展示规则 |
|------|------|
| 表格单元格无值 | `--` |
| 描述列表无值 | `--` |
| 数值为空 | `--` |
| 百分比为空 | `--` |
| 时间为空 | `--` |
| 标签列表为空 | `--` 或 `无标签`，二选一后全局统一 |

【删除建议】不建议混用以下空值：

- `暂无`
- `无`
- `空`
- `/`
- `-`

建议默认统一为：`--`

### 3.2 空态组件文案

【新增】空态建议使用如下统一模板：

| 场景 | 主文案 | 副文案 | 按钮文案 |
|------|------|------|------|
| 列表为空 | `暂无数据` | `当前还没有可展示的数据` | `刷新` |
| 搜索无结果 | `未找到匹配结果` | `请调整筛选条件后重试` | `重置筛选` |
| 未创建任务 | `暂无巡检任务` | `可先创建任务后查看执行结果` | `创建任务` |
| 未创建模板 | `暂无模板` | `可通过新建或 AI 生成方式创建模板` | `新建模板` |
| 图表无数据 | `暂无数据` | `当前时间范围内没有可展示的数据` | `刷新` |

### 4.1 主操作按钮

【新增】推荐统一如下：

| 场景 | 推荐文案 |
|------|------|
| 新增 | `新建` |
| 新建巡检任务 | `创建任务` |
| 新建联合巡检 | `创建联合巡检` |
| 保存 | `保存` |
| 保存并执行 | `保存并执行` |
| 编辑 | `编辑` |
| 删除 | `删除` |
| 查看详情 | `查看详情` |
| 重试 | `重试` |
| 刷新 | `刷新` |
| 导出 | `导出` |
| 立即执行 | `立即执行` |

## 6. 页面级状态说明

### 6.1 列表页

【新增】列表页至少应具备以下状态：

| 状态 | 页面表现 |
|------|------|
| `loading` | 表格 skeleton 或 loading |
| `empty` | 显示 EmptyState |
| `error` | 显示错误提示和重试入口 |
| `hasData` | 正常展示筛选区、表格、分页 |

### 6.2 表单页 / 抽屉 / 弹窗

【新增】表单页至少应具备以下状态：

| 状态 | 页面表现 |
|------|------|
| `init` | 初始值加载中 |
| `editing` | 可编辑 |
| `submitting` | 按钮 loading，禁止重复提交 |
| `submitError` | 展示错误反馈，不清空用户输入 |
| `readonly` | 详情态不可编辑 |

## 7. 给 IDE / AI 的使用说明

【新增】把本规范交给 IDE 时，建议附带以下要求：

```md
1. 状态值必须优先复用本文件中的枚举，不允许重新命名同义状态。
2. 展示文案必须从统一映射表获取，不允许在组件内部硬编码中文状态。
3. 空值统一显示为 `--`，空态统一使用 EmptyState。
4. 如果后端返回的状态值不在规范中，先映射为 `unknown`，并输出“新增状态建议”。
5. 删除、停用、取消执行等危险操作，必须使用统一确认文案模板。
```
