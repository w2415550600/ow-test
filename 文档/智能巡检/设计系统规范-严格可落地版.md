# 设计系统规范（严格可落地版）

> 目标：对齐 `project.md` 第四部分结构，确保前端可以直接映射到 `variables.scss / override.scss / custom.scss`。
> 原则：所有视觉参数必须 token 化，禁止业务页面硬编码。

## 四、设计系统规范

### 4.0 Token 命名与分层规则

| token 名称 | 色值 | 用途 |
|------|------|------|
| `--ref-*` | `基础值` | 原子层（不直接在业务中使用） |
| `--sys-*` | `语义值` | 系统语义层（组件默认使用） |
| `--comp-*` | `组件值` | 组件层（按钮、表格、弹窗等） |
| `--biz-*` | `业务值` | 业务层（仅在 custom.scss 使用） |
| `--color-{group}-{role}-{state}` | `命名规则` | 颜色命名：组/角色/状态（default/hover/active） |
| `--sys-space-{n}` | `命名规则` | 间距仅使用 0/2/4/8/12/16/24/32 |
| `token 引用方向` | `命名规则` | 允许 `ref -> sys -> comp -> biz` 单向映射，禁止反向引用 |
| `UI 变量出口` | `工程规则` | 最终只允许在 `variables.scss` 暴露 CSS Variables，组件和页面样式禁止重新定义同名 token |

### 4.1 主题模式

项目采用暗色主题，推荐把语义 token 映射到 Element Plus 变量，降低覆盖成本。

组件库策略必须明确如下：

1. 页面基础组件以 `Element Plus` 为主。
2. `Ant Design Vue` 仅在存量页面或 Element Plus 无等价能力时使用。
3. 同一页面禁止混用两套视觉风格相近的基础组件，例如 `el-table` 与 `a-table`、`el-dialog` 与 `a-modal` 不得并存。
4. 交给 IDE 生成页面时，默认组件前缀使用 `el-`，除非需求文档显式指定其他组件。

```
建议样式加载顺序：
1. variables.scss        # ref/sys/comp token
2. skyeye-ai-driven-kit  # 内部图标与业务基础样式（如项目中使用）
3. element-plus          # 组件库基础样式
4. reset.scss            # 样式重置
5. override.scss         # 全局覆盖（只改语义，不改业务）
6. custom.scss           # 业务布局与页面样式
```

| token 名称 | 色值 | 用途 |
|------|------|------|
| `--sys-theme-mode` | `dark` | 主题模式标识 |
| `--sys-bg-page` | `#0C0F20` | 页面主背景 |
| `--sys-bg-container` | `#171A2A` | 卡片/容器背景 |
| `--sys-bg-overlay` | `#1F2336` | 浮层背景 |

### 4.11 页面布局约束

| 规则项 | 规范 |
|------|------|
| 页面宽度策略 | 默认面向 `1440px` 设计稿实现，代码侧以 `min-width: 1280px` 保障主后台布局不塌陷 |
| 外层结构 | 后台页面统一为 `sidebar / page-header / page-content` 三段式 |
| 内容区留白 | 页面左右内边距默认使用 `--biz-page-padding`，禁止页面自行设 20/18/30 等非 token 值 |
| 模块垂直间距 | 相邻业务模块仅使用 `--biz-section-gap` |
| 卡片内部结构 | 卡片内统一 `header -> body -> footer/action`，若无 footer 不得额外补空白区 |
| 栅格策略 | 列表/卡片宫格优先使用 24 栅格或 `grid-template-columns`，并明确列间距使用 token |

### 4.14 响应式与适配规则

| 规则项 | 规范 |
|------|------|
| 最小支持宽度 | `1280px` |
| 设计基准宽度 | `1440px` |
| 超宽屏策略 | 内容区最大宽度可限制在主容器中，避免卡片被无限拉伸 |
| 窄屏策略 | 低于最小宽度时优先出现横向滚动，不强行压缩侧栏和表格 |
| 表格适配 | 列多时允许横向滚动，禁止自动挤压到换行 |
| 筛选区适配 | 先换行为两行，其次折叠高级筛选，不允许按钮掉到孤立第三行 |

### 4.15 可访问性与工程约束

| 规则项 | 规范 |
|------|------|
| 对比度 | 文本与背景至少满足后台场景可读性，弱文案不得低到不可辨识 |
| 点击热区 | 图标按钮最小可点击区域建议不小于 `28px * 28px` |
| 键盘操作 | 弹窗、抽屉、下拉、表格行操作需可通过键盘聚焦 |
| Tooltip 策略 | 仅在文案截断或图标无文案时使用，不允许全页面滥用 |
| 国际化预留 | 表格列宽、按钮宽度、标题区至少预留中英文长度差异 |
| 日期与数字 | 时间、百分比、风险值、主机数等格式必须在文档中给出展示样例 |

### 4.16 提供给 IDE 的实现约束

把这份文档交给 IDE 或 AI 生成页面时，建议额外附上以下硬性指令：

```md
1. 仅使用本文档中已有 token，不允许自行创造新的颜色、字号、间距字面量。
2. 默认使用 Element Plus 组件，除非我明确点名其他组件。
3. 页面必须输出：
   - 页面结构说明
   - 对应 token 使用说明
   - 缺失 token 清单
4. 如果设计稿信息不足，不要自行脑补视觉细节，先回报缺失项。
5. 业务样式只能写在 custom.scss 或页面 scoped style 中，禁止改写 variables.scss 既有语义。
6. 遇到状态组件、表格、弹窗、筛选区时，优先复用通用封装，不要每页重复造轮子。
```

## 落地执行规则（开发侧）

| token 名称 | 色值 | 用途 |
|------|------|------|
| `规则-01` | `禁止硬编码` | 颜色/圆角/阴影/间距不得直接写字面量 |
| `规则-02` | `语义优先` | 组件优先使用 `--sys-*`，业务再映射 `--biz-*` |
| `规则-03` | `状态完整` | 所有可交互色必须提供 default/hover/active |
| `规则-04` | `只增不改` | 基础 token（`--ref-*`）仅新增，不直接改历史值 |
| `规则-05` | `变更可追溯` | 新增 token 必须附用途、影响范围、替代关系 |
| `规则-06` | `组件库单一优先` | 单页面默认只使用一套主 UI 组件库风格 |
| `规则-07` | `缺失先登记` | 设计稿未定义的 token、状态、尺寸先登记缺失，不允许 AI 自行拍脑袋补齐 |
| `规则-08` | `样式职责清晰` | `variables.scss` 管 token，`override.scss` 管全局组件，`custom.scss` 管业务布局 |
| `规则-09` | `页面骨架统一` | 后台页面统一三段式骨架，禁止每页自定义顶层布局 |

## 附录 F：页面验收检查表

每个页面在交付前，建议至少做一次自检：

| 检查项 | 验收标准 |
|------|------|
| token 使用 | 无硬编码颜色、字号、圆角、阴影、间距 |
| 组件一致性 | 同类组件样式一致，无同页双组件库混用 |

| 状态完整性 | loading / empty / disabled / error 等状态齐全 |

| 表单质量 | 校验提示、必填样式、按钮布局一致 |
| 响应式 | 1280px 下不塌陷，超宽屏不失衡 |
| 文案一致性 | 状态、按钮、空态、提示文案符合统一规范 |
| 可复用性 | 重复区块是否已抽为组件 |
| 风险登记 | 所有基于推断的实现都已注明 |
